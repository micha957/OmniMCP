# 运营工作台

工作台是独立的本地程序，通过 OmniMCP 读取平台、准备内容，并把写操作提交到确认队列。

**当前运行方式（2026-11-06 起，由账号所有者决定）：** 小红书的发布、评论和回复由 AI 负责，不再需要点确认，由 `OMNIMCP_AUTO_APPROVE` 控制，并带每日上限。未列入的工具，以及其他平台，仍然进入确认队列。清空这个变量即恢复逐条确认。

## 确认流程

```text
通知 / 到期选题 → AI 生成草稿 → 你检查后提交确认 → 确认队列 → 你批准 → 服务端按原内容执行 → 回执写回草稿
```

- 所有带 `Mutating` 的工具（包括通用浏览器的 `click`、`fill`）都只生成提案，返回 `approval_id`，不会执行。
- 批准绑定工具、账号和内容哈希，只生效一次；内容修改后，原来的确认页面无法再批准。
- 相同内容不会重复进入队列。24 小时内已成功或已驳回的内容直接返回原结果。
- 点击发送后无法确认结果时，状态为“结果不明”。请先到平台核对，再决定是否重试，系统不会自动重试。服务在执行中重启，也按结果不明处理。
- 提案 72 小时未确认会过期。排期到时只进入队列，不会自动发布。
- MCP 没有批准工具，MCP 令牌也打不开确认接口。

确认入口有三个：工作台的「待确认」、OmniMCP 的 `http://127.0.0.1:8090/approvals`（手机宽度可用），以及在终端运行 `omni approvals approve <id>`。

**安全边界：** 未设置 `OMNIMCP_APPROVAL_TOKEN` 时，确认接口只接受本机请求。如果 AI 能在同一台机器上执行任意 shell 命令，它也能访问 localhost。这种情况下请设置该口令，并且不要放进 AI 可读取的环境或文件里。远程确认同样需要这个口令。

## 启动

在仓库根目录运行：

```bash
go run ./cmd/agentops
```

打开 [运营工作台](http://127.0.0.1:8091)。首次启动会创建 `data/agentops/state.json`，包含拼豆工坊的产品知识、开发者角色、六个搜索词和三篇初始笔记草稿。再次启动会读取已有内容。

不配置模型也可以编辑、整理和导出初始内容，以及收集真实帖子、记录对话。初始草稿均按产品尚未上线的事实撰写，每篇附待准备的真实配图清单。

## 同步、数据与排期

绑定账号后，「同步平台」会依次检查登录状态、导入新评论并采样账号数据。同一条评论不会重复导入；对方有新回复时，对话重新进入待处理，回复目标改为最新评论。

| 能力 | 小红书 | B 站 | 知乎 | 抖音 | 其他平台 |
| --- | --- | --- | --- | --- | --- |
| 登录检查 | ✓ | ✓ | ✓ | ✓ | YouTube、TikTok |
| 通知导入 | ✓ | ✓ | ✓ | 尚未支持 | 尚未支持 |
| 账号数据采样 | ✓（含浏览量，来自笔记管理页） | ✓（含播放量） | ✓（回答为喜欢数，不是赞同数） | ✓（含播放量） | 尚未支持 |
| 回复指定评论 | ✓ | ✓ | 尚未支持 | 尚未支持 | 尚未支持 |
| 发布、评论提案 | ✓ | ✓ | ✓ | ✓ | 快手、微博（评论）、YouTube、TikTok 已映射到现有工具 |

第一次同步只导入最近 14 天的评论，不会为旧评论写回复。定时同步至少间隔 2 小时，手动同步不受限制。**频繁读取可能让真实账号被平台限制**，不要把间隔改短。

通知读取结果带覆盖范围。`complete=false` 表示还有更早的条目没有读取，不能当作没有新消息。数据页只显示平台实际读到的内容，不做估算。

「内容日历」按日期显示排期。状态为“内容已整理”的草稿到时间后进入待确认队列。素材可上传到素材库（默认 `data/agentops/assets`）；较大的视频直接放进这个目录，再在草稿里填写绝对路径。

连接模型后，笔记草稿可以改写到其他平台，改写结果是一份新草稿，同样需要确认。

## 内容质量

每篇草稿都会过一遍 AI 感检查，结果显示在编辑窗口，只提醒不拦截。发布后「数据复盘 → 发布实验」按 24 小时、72 小时、7 天记分。判断依据、实验记录和下一步计划见[内容优化手册](CONTENT_PLAYBOOK.md)。

## 模型配置

程序读取环境变量。可以在本机 `.env` 中配置，再按仓库 README 的方式加载文件；密钥文件不提交 Git。

```bash
OMNIMCP_AGENT_BASE_URL=https://your-model-service.example/v1
OMNIMCP_AGENT_MODEL=your-model-id
OMNIMCP_AGENT_API_KEY=your-service-key
```

模型名与密钥须属于所配置的服务。未设置专用密钥时，程序回退到 `OPENAI_API_KEY`。基础地址填写到 `/v1`，程序调用其 `/chat/completions` 路径，使用 `messages` 和 `max_completion_tokens`。服务需要支持这一接口格式，具体模型由用户配置。

配置后重启程序。界面中的「模型已配置」表示参数已提供，实际可用性由运行结果确认。模型非成功响应、结果截断、无效 JSON、未知产品事实和超长内容会显示在运行记录中。

## 一个实际使用流程

1. 在「角色设置」调整角色表达、目标、搜索词、规则与内容选题。
2. 在「参与机会」添加真实小红书帖子的链接、正文和必要讨论；也可以连接浏览器后从平台搜索。
3. 在「对话跟进」记录实际收到的消息及此前语境。
4. 点击「准备下一轮」。优先处理新回复，其次判断候选帖子，再准备尚无草稿的选题。
5. 在「内容草稿」检查依据、编辑文字、添加真实素材，然后点“提交确认”。
6. 对方有新回复时，在原对话内记录新消息，下一轮会按更新后的上下文处理。
7. 点击「导出内容」得到包含草稿和素材清单的 Markdown 文件。

同一来源已准备的内容会去重。重启不会重新生成已经保存的草稿。修改选题标题会作为新选题；已有草稿可直接编辑。配置或对话在生成途中变化时，旧结果不会覆盖新上下文。

## 从真实平台读取

先启动原有服务，并在浏览器中连接 OmniMCP 扩展、登录小红书：

```bash
go run ./cmd/omnimcp
```

工作台的「角色设置 → 浏览器平台账号标识」填写扩展里对应的账号标识，然后在「参与机会」点击「从平台搜索」。当前每轮最多使用三个搜索词、新增五个帖子，会读取正文和已加载的部分评论，再交给后续准备流程。

工作台只能调用 `internal/agentops/mcp.go` 中列出的读取工具，写操作也限定在 `actions.go` 的工具列表内。模型只提供文字，不能决定工具、账号或发送目标；目标来自平台读取的结果。

MCP 默认地址为 `http://127.0.0.1:8090/mcp`，可使用 `OMNIMCP_AGENT_MCP_URL` 修改。认证优先读取 `OMNIMCP_AGENT_MCP_TOKEN`，否则读取 `OMNIMCP_API_TOKEN`。账号标识用于路由，实际身份由对应浏览器 Profile 的登录状态决定。

## 定时与暂停

在角色设置中开启「按计划自动准备本地草稿」，设置 5–1440 分钟的间隔及每轮 1–10 个任务。若同时开启平台搜索，需要先绑定账号。初始状态为手动运行，间隔默认 30 分钟，每轮三个任务。

每个进程同一时间执行一轮任务，每轮最长五分钟，单次模型请求最长 75 秒。每轮结束后才安排后续运行；界面可在运行记录中停止本轮。关闭自动准备并保存配置会停止当前运行。手动运行保持可用。

## 数据与当前边界

- 状态采用带互斥锁的内存快照和原子替换的 JSON 文件，失败写入不修改内存。文件按本机私有权限创建。
- 同一状态文件仅供一个进程使用。后续需要多进程和更大的历史库时，再迁移数据库与任务队列。
- 状态上限为 32 MB；最多保留 100 轮运行记录，候选帖子上限 1000 个，对话 500 段，数据样本 500 条。请定期导出和归档数据。
- 运营阶段可在设置里切换。上线前模型只按开发中表述；切到“已上线”前，请更新产品事实和访问入口。
- 版本 1 的状态文件在首次启动时自动升级到版本 2，只增加字段。
- 当前模型调用发送角色、产品知识及待处理上下文；不向模型发送账号路由标识和帖子链接中的查询参数。模型密钥只从服务端环境读取。
- 工作台仅监听本机回环地址，不提供远程访问入口。
